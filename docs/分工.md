# 四人分工（完整作品版）

目录就是边界。不要改别人的目录，通过 `data/venues/*.json` 和 `compile_and_run()` 交接。

| 角色 | 目录 | 交付 | 怎样算做完 |
|---|---|---|---|
| **A 标注** | `data/venues/`、`data/schema.json` | 把 `verified: false` 的例句换成当天官网原文并改为 true。目标 30 条，约 8 条 `heldout` | `python eval/check_corpus.py` 通过，新增馆有 `gold.ticket` 或明确 `gold: null` |
| **B 编译** | `rulecard/extract.py`、`execute.py`、`segment.py`、`schema_check.py`、`repair.py`、`flow.py` | 新句式抽错时改抽取或修补，不写死馆名；结构校验挡住残缺规则 | `python -m unittest tests.test_pipeline` 通过 |
| **C 评测** | `eval/`、`rulecard/direct.py`、`rulecard/errors.py` | 三路对照（种草 / 首个数 / 编译）、错因归类、`eval/latest.json` 与 `docs/report.html` | `python eval/run_eval.py && python eval/render_report.py`，README 数字与 latest.json 一致 |
| **D 演示** | `demo/` | 门票页四格、三路对照、六步轨迹、可改原文；现场从选馆到四格不中断 | 留出馆当场改原文仍能出结果，预存答案随改动隐藏 |

## 交接接口

```python
compile_and_run(venue, age, height_m, benefits=[])
```

返回 `compiled.ticket`（free/half/full）、触发句、`baseline_ticket`、`first_number_ticket`、`ablation_ticket`、`errors`、`schema_issues`、`trace`。没有 `gold` 时三条 `*_correct` 为 null，不进准确率。

## 交稿前清单

1. A：核对馆从 2 条涨到 15 条以上，每条 `source` 是当天 URL。
2. B：A 换入的新句式若抽错，先改抽取，再补测试，不许在数据里迁就抽取器。
3. C：报告里的数字必须能由 `eval/latest.json` 复算；错因分布写进答辩稿。
4. D：录屏走一遍「留出馆 → 改身高 → 改原文 → 看三路分歧」，断网也要能跑。
