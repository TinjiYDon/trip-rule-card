# 可扩展性

规则卡的结构是「散文 → 结构 → 执行」。加新能力时只动一层，不动另外两层。

## 已经留好的口子

| 要加什么 | 动哪里 | 不用动 |
|---|---|---|
| 新句式（如「1.1 米至 1.3 米购优待票」） | `rulecard/extract.py` 加一个模式，补一条测试 | 执行器、演示 |
| 新票种（如「优待票」） | `execute.py` 的 `TICKET_LABEL` 与 `_band` | 抽取返回的字段名不变 |
| 新人群（老人、军人） | `extract.py` 的 `_ages` / `_benefits`，`data/schema.json` 加 gold 字段 | 四格卡片结构不变 |
| 新错因 | `rulecard/errors.py` 的 `LABELS` 和 `classify` | 评测汇总自动带上 |
| 接真实模型 | 配置 `RULECARD_LLM_*` 三个环境变量；或改 `llm_propose.py` | 校验和执行不变，草案过不了校验就丢弃 |
| 嵌进真实门票页 | `demo/index.html` 换成产品组件，接口仍是 `compile_and_run()` | 整条流水线 |

## 明确不做

- 不做行程规划、不预测客流、不接真实库存。这些会把「交易前这一下」的边界冲淡。
- 不把模型输出直接当结论。模型只能提议结构，符号执行才是结论。

## 数据流的可替换点

```
分句 → 抽槽 → 校验 → 修补 → 执行 → 对照
        ↑可换成模型草案      ↑可换成求解器
```

抽槽可以换成模型，校验不变；执行可以换成约束求解器，输入结构不变。这两个替换点写在 `docs/数据流.md` 的图里。
